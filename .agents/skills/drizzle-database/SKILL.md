# Drizzle Database

Read `AGENTS.md` first. A query-only change needs **no** migration and **no** seed.

## 1. Where things live

| Need | File |
|---|---|
| All tables, enums, relations | `server/database/schema.ts` (single file) |
| Runtime connection (inside Nitro) | `server/database/client.ts` → `useDb()`, `schema` |
| Permission codes, default roles, admin user | `server/database/seed.ts` (`RESOURCES` × `ACTIONS`) |
| Generated SQL + journal | `drizzle/*.sql`, `drizzle/meta/_journal.json` |
| drizzle-kit config | `drizzle.config.ts` (reads `NUXT_DATABASE_URL`) |
| Query examples | list + joins: `server/api/appUser/index.get.ts`; transaction: `server/api/appUser/index.post.ts`, `server/api/appRole/index.post.ts` |
| Not related to Drizzle migrations | `server/database/mysql/`, `server/database/migrate/` (MySQL import tool — read only for import tasks) |

## 2. Table template (new ordinary data table)

```ts
// server/database/schema.ts — reuse the local helpers, do not redefine them
export const xyz = pgTable('xyz', {            // table name: snake_case
  id: id(),                                   // Snowflake bigint PK, generated by the app ($defaultFn → nextId())
  name: varchar('name', { length: 255 }).notNull(),
  active: boolean('active').notNull().default(true),
  ownerId: bigint('owner_id', { mode: 'bigint' }).references(() => appUser.id), // FK: bigint mode 'bigint'
  ...auditFieldsSoftDelete()                  // deleted, createdDate, createdUser, updatedDate, updatedUser
}, (t) => [
  index('idx_xyz_owner_id').on(t.ownerId)     // add indexes for columns you filter by
])
```

| Table kind | Pattern to copy |
|---|---|
| Ordinary entity (CRUD page) | `id()` + `...auditFieldsSoftDelete()` (e.g. `appRole`, `aiDocumentMeta`) |
| Many-to-many junction | two FK bigint columns + composite `primaryKey` (e.g. `appUserRole`, `rolePermission`) |
| Child key/value rows | FK + composite PK (e.g. `aiDocumentMetadata`) |
| Append-only log | `id()` + explicit timestamp columns, no soft delete (e.g. `auditLog`) |

Rules: TS property camelCase, DB column snake_case; never `serial`, `bigserial`, or
`uuid` PKs; add a `relations(...)` block only if you will use `db.query.*` with `with`.

After adding a table, also add its client model to `app/types/models.ts`
(`export interface Xyz extends Id { ... }`, IDs typed as `IdType`/string).

## 3. Query cheatsheet

```ts
import { and, count, eq, inArray, ne, aliasedTable } from 'drizzle-orm'
import { schema, useDb } from '#server/database/client'
const db = useDb()

// single row: explicit columns + soft-delete filter + limit(1)
const [row] = await db.select({ id: schema.xyz.id, name: schema.xyz.name })
  .from(schema.xyz)
  .where(and(eq(schema.xyz.id, BigInt(id)), eq(schema.xyz.deleted, false)))
  .limit(1)

// same table joined twice → aliasedTable (see appUser avatar/cover)
const avatar = aliasedTable(schema.fileManager, 'avatar_table')

// related writes → one transaction, use tx (not db) inside
await db.transaction(async (tx) => {
  const [created] = await tx.insert(schema.xyz).values({ name }).returning({ id: schema.xyz.id })
  await tx.delete(schema.xyzTag).where(eq(schema.xyzTag.xyz, created!.id))
  if (tagIds.length) await tx.insert(schema.xyzTag).values(tagIds.map((t) => ({ xyz: created!.id, tag: BigInt(t) })))
})
```

- Paged lists: build data **and** count queries with the same joins, both ending in
  `.$dynamic()`, then call `paginate()` (details in `nitro-backend`). Put the
  `deleted = false` filter in `paginate({ where })` so both queries get it.
- Soft delete = `update(...).set({ deleted: true })`, not `delete()`, for tables with `deleted`.
- Throwing inside `db.transaction` rolls everything back — use this for validation that
  depends on writes (see `appUser/index.post.ts`).
- Do not rewrite login/refresh/logout into transactions; they are separate writes by design.

## 4. Bigint IDs (most common bug source)

| Direction | Do |
|---|---|
| Client → server | IDs arrive as strings. Validate numeric, then `BigInt(id)` |
| Server → client | `id.toString()` (or a `modelMapper` function). `server/plugins/bigint.ts` also serializes stray bigints |
| Comparing | `BigInt(a) === BigInt(b)` or compare strings. Never compare a bigint/string ID with a number |
| Client code | Treat IDs as strings. Never `Number(id)` (Snowflake IDs exceed 2^53) |

## 5. Schema change procedure (only when the task needs it)

1. Read `drizzle/meta/_journal.json` and the latest SQL file. Only files named in the
   journal are applied; keep one SQL file per number (never add a second `000N_*.sql`).
2. Edit `server/database/schema.ts`.
3. `pnpm db:generate` → open the new SQL file and check it contains only your change
   (no unexpected drops/renames). Never hand-edit a migration that has been applied.
   Raw SQL/views: `pnpm drizzle-kit generate --custom`.
4. `pnpm db:migrate` **only** if applying to a known, intended database is in scope.
   Otherwise stop and report that the migration was generated but not applied.
5. `pnpm db:push` is for throw-away local databases only.

## 6. Permission seed

- New permission-based module → append its snake_case table name to `RESOURCES` in
  `server/database/seed.ts`; this yields `<table>_{list,view,add,edit,delete}`.
- `pnpm db:seed` is idempotent: it inserts only missing permission codes (checked by code,
  since `permission.code` has no unique constraint), creates Admin/Viewer only if missing,
  grants all seeded codes to Admin and `_list`/`_view` to Viewer (`onConflictDoNothing` on the
  composite PK), and creates `admin@example.com` only if missing (password never changed).
- So rerunning the seed is the way to deliver new codes to an existing database — but it
  writes data: run it only when applying permissions to a known, intended database is in scope.

## 7. Done checklist

- [ ] Query selects explicit columns, filters soft-deleted rows, uses `limit(1)` for single rows.
- [ ] Multi-table writes are in one transaction.
- [ ] IDs converted at the boundary; no number comparisons.
- [ ] Schema change: generated SQL reviewed; journal updated by drizzle-kit, not by hand; report whether and where it was applied.
- [ ] `pnpm typecheck` passes (plus `pnpm build` for runtime changes). Do **not** run `pnpm lint`.
- [ ] Never run `db:migrate`, `db:seed`, or `db:push` just to "verify" a code change.
- [ ] Code outside a transaction that also touches files/Qdrant: write the order of writes and cleanup (see `ai-rag` §4).
